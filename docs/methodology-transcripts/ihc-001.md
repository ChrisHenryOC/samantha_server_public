# Worked-example transcript — IHC-001 (compositional tier)

**Tier.** 3 — compositional with ≥2 primitives, deepest-nested predicate
in the corpus
([decision-gate.md § "Worked-example candidates"](../rule-breakdown/decision-gate.md#worked-example-candidates)).

**Methodology.** [`rule-authoring-methodology.md`](../rule-authoring-methodology.md)
§§ 1–4.

**Date.** 2026-05-05. **Session.** Claude Code (Opus 4.7); methodology
applied end-to-end with the primitive catalog from
[`decision-gate.md` § "Final primitive set"](../rule-breakdown/decision-gate.md#final-primitive-set)
exposed as the tool vocabulary.

The transcript is verbatim from the authoring session: input prompt,
the assistant's reasoning and tool-style calls, the emitted YAML, and
the post-hoc annotations required by phase-1 plan § 7.4. Compared with
ACC-001 (Tier 1) and ACC-006 (Tier 2), this rule is the stress test:
three nesting levels, six distinct primitive types, two cross-cutting
concerns (HER2 added at IHC review + the same fixation-tolerance check
ACC-005 and ACC-006 perform at intake), and the publication-quality
demonstration of fail-closed null semantics on `fixation_time_hours`.

## 1. Input prompt

Given to the assistant as the authoring task. Quoted as delivered.

> **Task.** Author a deterministic rule encoding the following SOP
> fragment from `knowledge_base/rules/fixation_requirements.md`
> "IHC-001 — HER2 Added with Fixation Out of Tolerance":
>
> > "If a pathologist adds HER2 at H&E review (i.e., HER2 was not on
> > the original order but appears as an `added_marker` on the
> > `pathologist_he_review` event), the laboratory must verify that
> > the specimen was fixed in formalin for between 6 and 72 hours
> > inclusive before staining. If the fixative is not formalin, OR
> > the fixation time falls outside `[6, 72]`, OR the fixation time
> > is unknown, reject the HER2 slide at IHC staining: stay in
> > `IHC_STAINING`, set the `HER2_FIXATION_REJECT` flag, and emit a
> > rejection outcome. The non-HER2 panel members continue normally."
>
> **Inputs available.**
>
> - The 9-primitive vocabulary (`IsNull`, `Equals`, `ThresholdGTE`,
>   `ThresholdLTE`, `InEnum`, `Contains`, `BooleanAnd`, `BooleanOr`,
>   `Not`) with the null-discipline contract.
> - The dispatch contract (`step`, `applies_at`, `event_type`).
> - Field shapes on `Order`, `Event`, and `SpecimenContext`
>   (see `samantha_server/models/context.py`).
> - Outcome verb-prefix conventions
>   (`docs/rules/conventions.md`).
> - Inventory entry for IHC-001 in `docs/rule-breakdown/inventory.md`
>   (covering scenarios SC-048, SC-094; false-positive probe SC-049).
>
> **Output required.** A YAML file at
> `samantha_server/rules/specs/IHC-001.yaml` whose `RuleSpec`
> round-trips via the loader and routes the covering scenarios so
> that `applied_rules` contains `"IHC-001"` at the
> `ihc_staining_complete` step, with `HER2_FIXATION_REJECT` set on
> the resulting flags.

## 2. Assistant transcript

### 2.1 Reasoning — fragment classification

The SOP sentence has two trigger conditions joined by AND:

1. The pathologist added HER2 at H&E review. The H&E-review event
   carries `added_markers`, but the rule fires on the *next* event
   (`ihc_staining_complete`), so by the time IHC-001 evaluates the
   "HER2 was added at review" fact has already been distilled by the
   simulator into a boolean on the IHC event payload —
   `event.her2_added_at_review`.
2. The fixation conditions are unsuitable: fixative is not formalin
   OR `fixation_time_hours` is outside `[6, 72]` OR
   `fixation_time_hours` is missing entirely.

The verdict is rejection at IHC staining time — stay in
`IHC_STAINING` (no terminal transition; the rest of the panel
continues), set `HER2_FIXATION_REJECT` so downstream phases can
suppress HER2 reporting, and emit `rejected_her2_late_fixation`. The
`set_flags` mechanism is the cross-cutting carrier for the reject
verdict; subsequent rules (IHC-002 onward) read the flag, not the
predicate.

### 2.2 Tool call — read `Order` and `SpecimenContext` to confirm field shapes

```text
Read samantha_server/models/context.py
```

Result (excerpt):

```python
class Order(BaseModel, frozen=True):
    fixative: str
    fixation_time_hours: float | None
    ordered_tests: tuple[str, ...]
    ...

class Event(BaseModel, frozen=True):
    event_type: str
    event_data: Mapping[str, Any]
    ...

class SpecimenContext(BaseModel, frozen=True):
    order: Order
    current_state: str
    flags: frozenset[str]
    event: Event

    def field(self, name: str) -> Any:
        if name.startswith("event."):
            return self.event.event_data.get(name[len("event."):])
        if name == "flags":
            return self.flags
        ...
        return getattr(self.order, name, None)
```

Three relevant access paths:

- `fixative: str | None` (order body — relaxed to nullable
  to bring it in line with the rest of the order; null
  fixative is "missing info" and ACC-005's `Not(IsNull(fixative))`
  guard routes it to the holds path rather than firing the
  fixative-mismatch reject. By the time IHC-001 evaluates,
  intake-time gating has either rejected or routed the order, so
  the rule typically sees a populated string — but the predicate
  must still be correct against the full `str | None` surface).
- `fixation_time_hours: float | None` — order body, nullable, the
  null case is the publication-quality fail-closed example called out
  in the issue.
- `event.her2_added_at_review` — event-payload field, distilled by
  the simulator from the prior `pathologist_he_review` event's
  `added_markers` list.

The `SpecimenContext.field()` accessor handles the `event.<key>`
prefix transparently, so primitives can address event-payload keys
with the same `field=` parameter shape as order-body keys.

### 2.3 Tool call — primitive selection (HER2-added half)

The catalog turn produced this for the trigger:

```text
SelectPrimitive(
  Equals(field="event.her2_added_at_review", value=true)
)
```

Justification, recorded in the session log:

- The bare shape published in upstream summaries
  ([`decision-gate.md` § "Worked-example
  candidates"](../rule-breakdown/decision-gate.md#worked-example-candidates)
  and [`rule-authoring-methodology.md`
  § 8](../rule-authoring-methodology.md#8-worked-example-transcripts))
  reads `Contains('event.added_markers', 'HER2')`. The canonical
  YAML uses the boolean-distilled form
  `Equals('event.her2_added_at_review', true)` instead. Same trade
  ACC-006 exposed: the published summary captures the predicate's
  *intent* (read the marker addition off the H&E-review payload);
  the canonical YAML captures the *encoding* (the simulator pre-
  computes the boolean on the IHC event so IHC-001 can dispatch on a
  single field rather than re-deriving the cross-event lookup at
  evaluation time). The inventory entry for IHC-001 documents the
  pre-computed-boolean contract explicitly:
  > "scenarios provide pre-computed `event.her2_added_at_review`,
  > `event.fixation_out_of_tolerance`, `event.her2_rejected`."
  Both upstream docs would benefit from a one-line reconciliation
  that says "the published shape is the intent; the YAML uses the
  pre-computed boolean per the event payload contract" — tracked as
  an editorial follow-up in the same parent issue.
- An alternative encoding (`Contains('event.added_markers', 'HER2')`
  reading from the *prior* event's payload) was considered and
  rejected: it would require the kernel to retain prior-event
  payloads in the dispatch context, which is the wrong abstraction
  boundary (the dispatch contract binds on the *current* event only;
  cross-event state lives in `flags` or in pre-computed event
  fields). Pushing the lookback into the simulator is the
  ugly-but-honest form for this kind of cross-event distillation.
- A boolean-true `Equals` against a payload field is unusually flat
  for a Tier 3 rule, but the depth lives in the *fixation* half of
  the conjunction; the trigger half is intentionally cheap because
  the simulator already paid the cost.

### 2.4 Tool call — primitive selection (fixation-unsuitable half)

```text
SelectPrimitive(
  BooleanOr(
    Not(Equals(field="fixative", value="formalin")),
    Not(ThresholdGTE(field="fixation_time_hours", value=6.0)),
    Not(ThresholdLTE(field="fixation_time_hours", value=72.0)),
  )
)
```

Justification:

- Three failure modes joined by OR: wrong fixative, under-fixed,
  over-fixed. Each is its own `Not(...)` of the success-side
  predicate. The dominant-case heuristic from methodology § 4 step 2
  prefers naming the failure side directly, but the 9-primitive set
  has no `NotEquals` and no strict-inequality threshold — so the
  failure side has no direct encoding. `Not(Equals(fixative,
  'formalin'))` is the documented form for "fixative is not
  formalin"; `Not(ThresholdGTE(.., 6))` and `Not(ThresholdLTE(..,
  72))` are the documented forms for the strict inequalities, the
  same shape ACC-006 uses.
- IHC-001 is one of three rules in the corpus where `Not(...)` cannot
  be eliminated by the dominant-case heuristic, per
  [`decision-gate.md` § "Final primitive set"](../rule-breakdown/decision-gate.md#final-primitive-set)
  (the other two are ACC-006 and ACC-008). The "three" here counts
  rules, not the three `Not(...)` wrappers inside this rule's own
  predicate. The methodology § 4 step 2
  worked example for ACC-006 documents the `BooleanOr`-of-negations
  form for numeric tolerances; this rule reuses it and adds a third
  disjunct for the non-numeric fixative check.
- An equivalent form
  `Not(BooleanAnd(Equals(fixative,'formalin'), ThresholdGTE(..,6),
  ThresholdLTE(..,72)))` was considered and rejected. By De Morgan
  it's logically identical, but it pushes the negation up one level,
  away from the primitive that actually fails — which hurts the
  receipt's diagnostic value (the auditor wants "the
  `ThresholdGTE` half failed", not "some compound success-condition
  failed"). The published convention names the *individual*
  violation. Same trade ACC-006 makes; same conclusion.
- The `BooleanOr`-of-three at this level is structurally why IHC-001
  is the deepest predicate in the corpus: the outer `BooleanAnd`
  sits over a `BooleanOr` whose three children are each `Not(...)`
  wrappers around leaves — root → BooleanAnd → BooleanOr → Not →
  leaf, three nesting levels and six distinct primitive types
  (`BooleanAnd`, `BooleanOr`, `Not`, `Equals`, `ThresholdGTE`,
  `ThresholdLTE`).

### 2.5 Reasoning — null semantics on `fixation_time_hours`

This is the publication-quality artifact for the fail-closed null
discipline; the issue calls out that the transcript should "explicitly
surface" this case in the annotation section. Worked through here so
the annotation can reference a derivation rather than restate it.

The order body allows `fixation_time_hours: None` whenever the
intake-time gate didn't catch it. ACC-009 rejects orders whose
fixation time is missing *and* whose fixative is formalin at intake;
but a HER2 order accepted by ACC-008 (the omnibus "anything else"
gate) without fixation logging can reach IHC with
`fixation_time_hours = None`. (This is the exact path
[`decision-gate.md` § "Null semantics rationale"](../rule-breakdown/decision-gate.md#null-semantics-rationale)
identifies as the load-bearing case for IHC-001.)

Per the primitive contract:

- `ThresholdGTE(None, 6.0)` returns `False` (fail-closed).
- `Not(False)` returns `True`.
- Likewise, `Not(ThresholdLTE(None, 72.0))` returns `True`.
- `BooleanOr(True, True, X)` is `True` regardless of `X`.

So when `fixation_time_hours is None`, the fixation-unsuitable
disjunct evaluates to `True` and IHC-001 fires — HER2 is rejected.
The verdict matches what one would *want* the lab to do (refuse to
stain HER2 when fixation cannot be verified) but the SOP fragment
quoted in the prompt does not literally cover the missing-value case.
The verdict is reached by the kernel-wide null-discipline policy, not
derived from the SOP text. **This is the canonical demonstration of
fail-closed semantics aligning with SOP intent without an explicit
`IsNull` guard predicate.** The rule needs no `IsNull` short-circuit;
the policy direction is correct without one.

A naïve author might add `IsNull('fixation_time_hours')` as a fourth
disjunct ("be explicit"). The encoding would still be correct — the
disjunct is redundant given the threshold primitives' fail-closed
behavior — but it would mask a load-bearing invariant: the
*reason* this rule is correct on null inputs is the primitive
contract, not the rule's own structure. Adding an explicit guard
hides the contract dependency from the next reader. The methodology
§ 1 null-discipline paragraph is what makes the explicit-guard
temptation resistible.

### 2.6 Tool call — dispatcher fields

```text
SetDispatch(step="IHC", applies_at="IHC_STAINING", event_type="ihc_staining_complete")
```

- `step="IHC"` — the SOP fragment is in the IHC bundle (per
  inventory § "SOP source coverage", IHC-001 is the only IHC-bundle
  rule sourced from `knowledge_base/rules/fixation_requirements.md`,
  while the rest come from `knowledge_base/sops/ihc_staining.md`).
- `applies_at="IHC_STAINING"` — IHC rules carry an explicit
  `applies_at` per the dispatch contract (methodology § 2 plus
  [`decision-gate.md` § "Dispatch contract"](../rule-breakdown/decision-gate.md#dispatch-contract)).
  The rule must evaluate when the order is in `IHC_STAINING`, which
  is where it sits *during* the IHC staining run, not after.
- `event_type="ihc_staining_complete"` — the simulator emits the
  pre-computed `event.her2_added_at_review` and the
  `event.fixation_out_of_tolerance` boolean on the
  `ihc_staining_complete` event, not on `pathologist_he_review`. The
  dispatch contract binds on the event whose payload carries the
  fields the rule reads; this is the only event whose payload
  carries `event.her2_added_at_review`.

The inventory entry's note that IHC-001 "fires on
`ihc_staining_complete`, not state-entry" is the discriminator: most
IHC rules fire on entering the corresponding `IHC_*` state, but
IHC-001 is unusual in that it dispatches by the staining-complete
*event*. Inventory § 5 ("IHC-001 is unusual") flags this directly.

### 2.7 Tool call — action and severity

```text
SetAction(
  transition="IHC_STAINING",
  set_flags=["HER2_FIXATION_REJECT"],
  outcome="rejected_her2_late_fixation",
)
```

- `severity=null` — IHC-step rules use `priority` rather than
  `severity` (methodology § 2 plus
  [`docs/rules/conventions.md`](../rules/conventions.md)
  § "severity vs priority"). `priority=1` here orders IHC-001 ahead
  of any other rule that might co-fire on `ihc_staining_complete`.
- `transition="IHC_STAINING"` — *unusual choice*: the rule fires
  inside `IHC_STAINING` and the verdict is to *stay* there. The
  rejection is communicated via the flag and outcome, not via a state
  transition. The non-HER2 panel members continue staining; only the
  HER2 slide is rejected. A naïve choice would be `DO_NOT_PROCESS`
  (matching ACC-006's verdict for the intake-time mirror), but
  `DO_NOT_PROCESS` would terminate the *entire order* — including the
  ER, PR, Ki-67 slides that the SOP says continue normally. The
  flag-plus-stay-in-state encoding is the only one that preserves
  the rest of the panel.
- `set_flags=["HER2_FIXATION_REJECT"]` — the cross-cutting carrier
  for the rejection verdict. Downstream rules (IHC-002 onward and
  the resulting/reporting phases) read the flag to suppress HER2 in
  QC, scoring, and the final report. Verified against the
  `VALID_FLAGS` frozenset in `samantha_server/models/context.py`.
- `outcome="rejected_her2_late_fixation"` follows the `rejected_*`
  prefix convention. Naming the cause ("late_fixation") rather than
  the trigger ("her2_with_bad_fixation"); the cause is what an
  auditor reading the receipt needs. The "late" descriptor in the
  outcome is slightly imprecise (the failure mode includes
  *under-fixation* too, not just over-fixation), but matches the
  established naming in the `knowledge_base/rules/` source and is
  preserved for cross-reference fidelity.

### 2.8 Emitted YAML

```yaml
rule_id: IHC-001
step: IHC
applies_at: IHC_STAINING
event_type: ihc_staining_complete
severity: null
priority: 1
# Deepest-nested predicate in the corpus and the canonical fail-closed
# null-semantics example. When fixation_time_hours is None, both
# threshold_gte and threshold_lte return False (per primitive contract),
# so the two surrounding Not(...) wrappers each return True and the
# BooleanOr fires — HER2 is rejected, which is the safe verdict when
# fixation cannot be verified.
# See knowledge_base/rules/fixation_requirements.md#IHC-001.
when:
  boolean_and:
    - equals:
        field: event.her2_added_at_review
        value: true
    - boolean_or:
        - not:
            equals:
              field: fixative
              value: formalin
        - not:
            threshold_gte:
              field: fixation_time_hours
              value: 6.0
        - not:
            threshold_lte:
              field: fixation_time_hours
              value: 72.0
action:
  transition: IHC_STAINING
  set_flags:
    - HER2_FIXATION_REJECT
  clear_flags: []
  outcome: rejected_her2_late_fixation
  panel: null
  branch: null
source: knowledge_base/rules/fixation_requirements.md#IHC-001
```

- `RuleSpec.model_validate(yaml.safe_load(...))` produced a frozen
  spec; the `when` predicate resolved to a 3-level tree
  (`BooleanAnd → {Equals, BooleanOr → 3× Not → leaves}`) with the
  expected field and value literals across all six primitives.
- Engine smoke against the covering scenarios under
  `tests/fixtures/scenarios/`:
  - `rule_coverage/sc-048.json` — HER2 added at H&E review,
    `fixation_time_hours = 5.0` (under 6h), formalin fixative.
    `event.her2_added_at_review = true`, fixation disjunct fires
    via the `Not(ThresholdGTE)` branch. IHC-001 fires on step 10
    (`ihc_staining_complete`); routes to `IHC_STAINING` with
    `HER2_FIXATION_REJECT` set.
  - `rule_coverage/sc-049.json` — *false-positive probe*. HER2
    added at H&E review, `fixation_time_hours = 6.0` (boundary —
    exactly the LTE threshold). The bare-`ThresholdGTE` returns
    `True` at 6.0 (≥ semantics, not strict), so `Not(...)` returns
    `False`. The bare-`ThresholdLTE` returns `True` at 6.0 (well
    inside ≤ 72), `Not(...)` returns `False`. Fixative is formalin,
    `Not(Equals)` returns `False`. The `BooleanOr` over three
    `False` disjuncts is `False`. IHC-001 *does not* fire; the IHC
    staining proceeds normally to `IHC_QC`. This scenario is the
    rule's red/green proof that the boundary is on the *valid* side.
  - `accumulated_state/sc-094.json` — same step 10 trigger as
    SC-048, then verifies that `HER2_FIXATION_REJECT` *persists*
    through IHC_QC (IHC-002), IHC_SCORING (IHC-006), RESULTING
    (RES-003), PATHOLOGIST_SIGNOUT (RES-004), and REPORT_GENERATION
    (RES-005). The flag is the cross-cutting carrier; downstream
    rules don't re-evaluate IHC-001's predicate.
- The emitted YAML is structurally identical to the canonical
  `samantha_server/rules/specs/IHC-001.yaml` (same primitive types,
  same field/value literals, same composition order, same dispatcher

## 3. Annotations

### 3.1 What worked

- **Pre-computed event-payload booleans collapsed the cross-event
  lookback.** The instinct on first read was to encode the HER2-add
  trigger as `Contains('event.added_markers', 'HER2')`, matching the
  bare shape published in the methodology summary and decision-gate
  worked-example column. The inventory entry's
  "scenarios provide pre-computed `event.her2_added_at_review` …"
  contract resolved this in one tool turn: the simulator distills
  the cross-event fact, the rule reads the boolean. No
  cross-event-state machinery needed in the dispatcher; no
  re-derivation at evaluation time. This is the same lesson ACC-006
  surfaces with its panel-membership encoding (rule reads what the
  context literally contains; preprocessing belongs upstream), and
  IHC-001 makes it stronger because the upstream layer is the
  *event simulator*, not the order body.
- **The `BooleanOr`-of-three negations was a one-line extension of
  the ACC-006 pattern.** ACC-006's transcript already established
  the `BooleanOr` of two `Not(...)` wrappers for the numeric range.
  Adding the third disjunct (`Not(Equals(fixative, 'formalin'))`)
  for the non-numeric fixative check did not require a separate
  derivation — the dominant-case heuristic plus the irreducible-
  `Not(...)` exception both apply identically. ACC-006 paid the
  authoring cost; IHC-001 reused the trade.
- **The fail-closed null derivation matched
  `decision-gate.md` § "Null semantics rationale" verbatim.** The
  decision-gate section calls IHC-001 out as the load-bearing case
  for the policy and walks through the exact derivation (`Not(False)
  → True → BooleanOr fires`). Re-reading that section before
  authoring meant the null-handling decision (no explicit `IsNull`
  guard) was made in one tool turn, with the explicit-guard
  alternative recorded as a rejected option rather than re-litigated.
  Building the methodology around a small set of canonical
  derivations and then citing them by reference is more efficient
  than re-deriving from first principles each time.
- **The transition-stays-in-state encoding for cross-cutting
  rejection was unsurprising once the panel-continues constraint
  was recognized.** The naïve `DO_NOT_PROCESS` choice (matching
  ACC-006's intake-time mirror) was discarded immediately on
  re-reading the SOP fragment's "non-HER2 panel members continue
  normally" line. The flag-plus-stay-in-state pattern is the only
  encoding that preserves the rest of the panel. A novice author
  unfamiliar with the flag mechanism could easily land on
  `DO_NOT_PROCESS` and ship a regression — flagged in § 3.3.

### 3.2 What required correction

- **Initial `event_type` was `pathologist_he_review`.** First pass
  bound the rule to the H&E-review event because that's where the
  HER2 add literally happens. The dispatch contract's "rule binds
  on the event whose payload carries the fields the rule reads"
  rubric flipped the choice once the trigger primitive was
  selected: `event.her2_added_at_review` is a key on the IHC event
  payload, not the H&E event payload. Methodology § 2 plus
  [`decision-gate.md` § "Dispatch contract"](../rule-breakdown/decision-gate.md#dispatch-contract)'s
  collision-risk note made the correction mechanical (one tool
  turn). The "where the SOP fact lives in time" intuition can be
  off by an event when the simulator distills cross-event state.
- **First draft used `severity: REJECT` by analogy with ACC-006.**
  ACC-006 carries `severity: REJECT`; the IHC-001 verdict reads as
  "rejection" in plain English; the `outcome: rejected_*` prefix
  reinforces the analogy. But the conventions table in
  [`docs/rules/conventions.md`](../rules/conventions.md)
  separates *severity* (an ACCESSIONING-step concept driving the
  HOLD/REJECT/PROCEED hierarchy) from *priority* (a numeric ordering
  for non-ACCESSIONING steps). IHC-001 is `step: IHC` and uses
  `priority: 1`, not `severity`. The correction took one re-read of
  the conventions doc; the semantic similarity ("rejection") is a
  red herring against the schema's structural distinction.
- **The `outcome` name nearly drifted to `rejected_her2_fixation`.**
  Initial draft dropped the `late_` qualifier on the grounds that
  the failure mode is a tolerance check, not a lateness check
  (ACC-006's outcome is `rejected_fixation_out_of_tolerance`, which
  doesn't carry a "late" descriptor). The
  `knowledge_base/rules/fixation_requirements.md#IHC-001` source
  uses "late_fixation" specifically, and cross-reference fidelity
  outranks naming consistency between sibling rules — the outcome
  is what an auditor cross-references against the SOP doc. The "late"
  term is slightly imprecise (under-fixation isn't lateness) but it
  matches the upstream artifact, and changing the name in the YAML
  would silently break the receipt-to-SOP traceability path.

### 3.3 What surprised

- **The fail-closed null path is not a corner case — it's the
  rule's `decision-gate.md`-documented load-bearing invariant.**
  Going in, the expectation was that the null case would be a
  footnote in the annotations ("here's how it happens to behave on
  null fixation_time_hours"). The decision-gate section names
  IHC-001 specifically as the publication-quality artifact for the
  fail-closed policy, and the issue prompts for the case to be
  surfaced "explicitly … in the annotation section". The surprise
  isn't that the rule handles nulls — it's that the rule was *chosen
  for the worked-example tier* in part because it does. The
  methodology's null-discipline paragraph is abstract; this rule is
  the concrete fixture. A future change to the threshold primitives'
  null contract (e.g., switching to null-propagation instead of
  fail-closed) would have to update this rule's behavior as well as
  the policy doc, and the annotation here is the bridge between the
  two. **The rule doubles as a regression test for the policy.**
- **`transition: IHC_STAINING` (stay-in-state) is the cross-cutting
  rejection encoding the corpus uses, not a special-case escape
  hatch.** Every other rejection in the rule corpus
  (ACC-005/006/008/009 etc.) uses `DO_NOT_PROCESS`, which terminates
  the order. IHC-001 is the only rule (verified by `grep` against
  `samantha_server/rules/specs/`) that rejects *part* of an order
  while keeping the rest progressing. The mechanism — same-state
  transition plus a `set_flags` carrier — is general enough that the
  next "reject one panel member" rule would reuse it, but no other
  rule in the current 40-rule corpus needs it. Inventory § 5
  ("IHC-001 is unusual") flags the `applies_at` quirk; the
  same-state-rejection encoding deserves an analogous note. Tracked
  as an editorial follow-up on the parent issue.
- **The corpus contains a false-positive probe (SC-049) at the
  exact threshold boundary.** SC-049's `fixation_time_hours = 6.0`
  sits *on* the LTE-of-`ThresholdGTE`-of-6.0 boundary. If the
  primitive were implemented as strict `>` instead of `≥`, the
  scenario would land in the wrong bucket — the rule would fire
  when SOP intent is "boundary is valid". This probe makes the
  primitive's inequality direction (`>=` vs `>`) into a
  scenario-checked invariant rather than a contract-buried
  footnote. The pattern (one false-positive probe per
  threshold-bearing rule, sitting on the boundary) is worth
  documenting as a corpus convention; ACC-006's covering set
  (SC-013, SC-014, SC-081, SC-082) has the same shape with
  off-boundary tests at 5.0 and 73.0 plus multi-rule scenarios, but
  no exact-boundary probe. ACC-006 might benefit from one. Tracked
  as a separate inventory follow-up (not blocking this transcript).
- **Six distinct primitive types is right at the corpus ceiling
  but doesn't strain the YAML.** The emitted YAML reads cleanly
  even though it nests three levels and uses
  `BooleanAnd / BooleanOr / Not / Equals / ThresholdGTE /
  ThresholdLTE`. The block-style indentation makes the structure
  readable; the inline-prefixed-key flow style would have collapsed
  it into a single unreadable line. The methodology should perhaps
  note that block style is mandatory for any rule with ≥3 nesting
  levels — the formatting choice isn't aesthetic, it's a
  reviewability constraint. Tier 1 rules (single primitive) can
  tolerate either style; Tier 3 rules cannot.
